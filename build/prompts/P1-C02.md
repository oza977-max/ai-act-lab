# Build Prompt: P1-C02 — Model smoke test (tracer bullet)

## Chunk Summary
Load the smallest candidate (Qwen3.5-0.8B, 4-bit MLX, pinned revision) in a child process, apply its chat template with thinking off, generate one greedy answer (400-token cap) for one sample case, and report seconds and peak memory. Exclusions (memory above 6.5 GB, crash, kill) are recorded by the parent, never fatal. Command: `python -m lab.bakeoff smoke --model qwen3.5-0.8b`.

## Spec Excerpt
- ADR-007: child process per model; peak memory read after generation; above 6.5 GB → distinct exit status; parent records exclusion from exit status or kill; no per-case timeout, 400-token cap.
- ADR-008: safetensors only; refuse `.py`, `.bin`, `.pt`, `.pkl`; never remote code; load the pinned revision.
- ADR-009: thinking off via template setting from `models.toml`; whole prompt is one user message.
- Slug must be a key in `models.toml` matching `^[a-z0-9._-]+$`.
- Generator protocol: `load()`, `generate(prompt) -> str`, `peak_memory_gb() -> float`.

## Framework Reference (pinned for mlx-lm 0.32.2, mlx 0.32.4)
- `mlx_lm.load(path_or_hf_repo, revision=..., trust_remote_code=False)` → `(model, tokenizer)`
- `tokenizer.apply_chat_template([{"role": "user", "content": prompt}], add_generation_prompt=True, tokenize=False, enable_thinking=False)`
- `mlx_lm.generate(model, tokenizer, prompt, max_tokens=400, sampler=mlx_lm.sample_utils.make_sampler(temp=0.0))` → `str`
- `mlx.core.reset_peak_memory()`, `mlx.core.get_peak_memory()` (bytes)
- `huggingface_hub.snapshot_download(repo, revision=...)` → local path
- `tomllib.load` (standard library) for the registry.

## TDD Approach
1. Acceptance test first: `python -m lab.bakeoff smoke --model qwen3.5-0.8b` exits 0 and prints seconds, peak memory below 6.5 GB, and the answer status. Skipped when the model is not cached. Red, commit.
2. Unit tests with a stub: registry validation (unknown slug, bad slug, missing keys); build-file check; template kwargs passed; child-runner outcomes (success, memory exceeded, crash, killed).
3. Realistic-fixture variant (TDD-3): a registry slug with path characters (`../x`), a build listing a `.py` file, a child that is killed by a signal.

## Spec Excerpt
- Answer record (cross-cutting.md): nine fields; tiers `prohibited, high-risk, transparency-only, minimal, out-of-scope, needs-human-review`.
- Output line (cross-cutting.md): `id`, `raw` (string or null), `seconds`, `error` (`null` or `missing`); a gold case with no line equals a line with `error: "missing"`. Only `evaluate` parses.
- ADR-005: scan raw text (max 4,000 chars) from each `{` with the standard JSON decoder; first object that decodes; this chunk checks only that `tier` is a known tier (full `validate` is P1-C03).
- Measure definitions: tier accuracy over all gold cases; answered = tier other than needs-human-review; answered-case accuracy over answered cases ("not defined" when none); unreadable and missing count as wrong and not answered; review said when gold says review / when it does not.
- Report: plain-English summary first; counts and IDs only, never raw text; header names model, prompt, guideline, gold-set versions and run date from `run.json`.
- 10-case fixture (data-and-evaluation.md): gold E01 prohibited, E02 high-risk area 4, E03 high-risk area 5, E04 transparency-only, E05 minimal, E06 minimal, E07 transparency-only, E08 out-of-scope, E09 minimal, E10 needs-human-review; outputs E01–E06 correct, E07 minimal, E08 minimal, E09 needs-human-review, E10 needs-human-review.

## Framework Reference
- `json.JSONDecoder().raw_decode(s, idx)` returns `(obj, end)` or raises `json.JSONDecodeError`.
- `dataclasses.dataclass(frozen=True)`; `argparse` for the CLI; `pathlib.Path.read_text(encoding="utf-8")`.
- pytest 9: `tmp_path` fixture; `subprocess.run([sys.executable, "-m", "lab.evaluate", ...], capture_output=True, text=True)`.

## TDD Approach
1. Acceptance test first (`test_p1c01_acceptance.py`): runs the CLI on a copy of the fixture; expects exit 0, stdout containing "7 of 10" and "6 of 8", and a `report.md` beginning with a plain-English summary. Run → red; commit the red state.
2. Unit tests demanded by its failures: parsing (`test_records.py`), measures (`test_evaluate.py`), including the all-review case (TC-EV-2-02).
3. Realistic-fixture variant (TDD-3, parsing domain): outputs with prose around the JSON, a fenced code block, an unreadable answer, a missing line, and an answer whose first `{` is not valid JSON.
4. Guard test (TC-GS-2-03): a throwaway git repository where a planted private term is blocked and a clean change passes.
5. Acceptance test → green; commit.

## Review Criteria
- Beck: every behaviour demanded by a failing test; tests name TC IDs.
- McConnell: malformed gold or output files stop with file, line and reason; duplicate ids and output ids not in gold are errors.
- Martin: no bare `except`; functions do one thing.
- Geifman & El-Yaniv: never report answered-case accuracy without the share answered; zero answered is "not defined".
- LANGSEC: `evaluate` is the only parser of `raw`; the runner stores text only.
- Report never contains raw model text (design review T13).

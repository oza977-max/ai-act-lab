## Spec Excerpt
- cross-cutting.md "Shared contract: the answer record": nine fields and rules (route required iff high-risk; area 1..8 and point iff annex-iii; legislation iff annex-i; flag boolean; at least one article except needs-human-review; review_reason iff needs-human-review; reason one sentence, at most 40 words); no date, deadline or duties field.
- data-and-evaluation.md ADR-005: scan at most 4,000 characters from each `{`, take the first object that decodes; duplicate, unknown or missing keys or any `validate` violation make the answer unreadable; never repair.
- data-and-evaluation.md `lab/records.py`: one-sentence rule (exactly one sentence-ending mark, at the end, ignoring abbreviation periods such as "Art." and "e.g."); `contains_date` must match "2 August 2026", "2 Aug 2026", "August 2026", "2026-08-02", "02/08/2026"; must not match "2027" alone, "Art. 113", "Annex III 4(a)", "Regulation (EU) 2024/1689".
- Measure "Dates found": answers whose raw text contains a date, over all gold cases with raw text; raw text scanned even when unreadable.

## Framework Reference
- `json.JSONDecoder(object_pairs_hook=...)` receives the list of key/value pairs, enabling duplicate-key detection; `raw_decode(s, idx)` returns `(obj, end)`.
- `isinstance(True, int)` is `True`: integer checks must exclude `bool`.
- `re` with `re.IGNORECASE`; `\s` matches Unicode whitespace (including no-break space) on `str` patterns.
- `dataclasses.fields`, `dataclasses.asdict`.

## TDD Approach
1. Acceptance test first (Red), committed.
2. Unit tests per rule, then minimal code.
3. Realistic-fixture variants (parsing domain): strings `"false"`/`"4"` for typed fields, `true` as an area, duplicate keys, extra keys, no-break spaces in dates, reason ending in an abbreviation, a reason with a decimal number.
4. Acceptance test Green, committed.

## Review Criteria (for Self-Review Loop — not construction)
- Beck: each rule demanded by a failing test; test names carry TC IDs.
- McConnell: every field checked for type before value; no rule silently skipped for an odd type.
- Martin: one small check per rule; messages name the field and the rule.
- Ramalho: `bool` excluded from integer checks; no mutation of records.
- LANGSEC: `parse_answer` stays the only parser; never repairs; duplicate keys rejected, not last-wins.
- Bach & Bolton: at least one realistic-fixture variant per function.
- Design rule (CLAUDE.md): dates never in the record; the detector flags them.

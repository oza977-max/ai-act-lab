Themes

T1 (Critical). Running in 8 GB is not designed — C-3, D-1, D-14

The spec says a model that "exceeds the limit" is excluded, but names no limit, no measurement, and no way to survive an out-of-memory kill, which ends the process before excluded.md can be written. The per-case timeout cannot be enforced inside one generation call. Fix: run each model in a child process; measure MLX peak memory per case; exclude above 6.5 GB; the parent records the exclusion from the exit status; replace the timeout with the token cap.

T2 (Critical). The review sheet cannot hold a complete record — B-1, B-2, C-8, D-8, B-10

The CSV has no columns for the Annex I legislation, the review reason or the guideline version, so the 5 Annex I and 10 needs-human-review cases can never pass the checker. Cell encodings for true/false, lists and empty values are undefined; gold check both validates and edits the sheet; the "doubt" decision has no defined effect; only the draft tier, not the full draft record, is kept for GS-5. Fix: add the missing columns; define encodings (true/false, ;-separated lists, empty means none); check only validates, build copies accepted proposals; a "doubt" blocks build until resolved; keep the full draft record.

T3 (Important, 5 panels). Run metadata has no home — A-1, A-8, B-3, B-5, C-2, D-11, D-12

Peak memory, prompt version, settings and model provenance are not in any file the evaluation or comparison reads; compare would have to scrape Markdown. Fix: bakeoff writes run.json (model, build, prompt version, settings, peak memory, mean seconds, date); evaluate writes metrics.json beside report.md; models.toml gains developer, jurisdiction and training-data disclosure; compare reads only JSON and TOML; name docs/decisions-log.md.

T4 (Important, 4 panels). Who parses a model's answer, and how — B-4, C-4, D-4, E-6

Both the runner and the evaluation could parse; "first complete JSON object" is undefined for braces in strings, decoys and duplicate keys; whether a rule violation makes an answer unreadable is unstated; "missing" has two representations. Fix: the runner stores raw text and seconds only; the evaluation alone parses, scanning with a standard JSON decoder, rejecting duplicate keys and extra fields, and treating a rule violation as unreadable; one representation of missing.

T5 (Important). Measures lack exact definitions — C-1, B-8, B-11, D-5, D-6

Numerator and denominator are not given per measure; citation format, the article table's shape, and what counts as citation overlap are undefined; which text is scanned for dates, and with which patterns, is unstated. Fix: a table of every measure with numerator, denominator and treatment of unreadable and missing answers; a citation grammar and articles.json shape; overlap at article level; dates scanned in the raw text with listed must-match and must-not-match examples.

T6 (Important). Statistics edge cases — C-7, D-7

Undefined: kappa when chance agreement is 1, Wilson at zero cases, percentile and random-generator choice, and comparing 0.79 with 0.80 on floating-point numbers. Fix: state each; report "not defined" for degenerate cases; compare kappa rounded to two decimals.

T7 (Important). Dates lookup contract — A-7, B-6, C-9, D-10

The command lacks the Article 50 and date flags; TOML cannot hold "no route"; several dates per tier do not fit one applies_from; unverified entries' behaviour clashes with owner approval; no field records a discrepancy. Fix: --art50 and --today flags; the string none for no route; a list of dated duties per entry; refuse unverified entries with a named error; plan_value and discrepancy_note fields; vocabulary imported from records.

T8 (Important). Re-label contract — A-4, B-7, D-9

No sheet columns, no stored build date or seed, no file for resolutions. Fix: gold build writes gold-v{N}.meta.json (build date, hash); relabel writes record.json (seed, date, ids) and resolutions.csv (id, first label, second label, resolution, guideline version); sheet columns id, description, relabel_tier, note.

T9 (Important). The first chunk never touches a model, and chunk order breaks — A-5, A-11, D-2, D-13

The riskiest seam (loading a model, its chat template, memory) is first exercised in Phase 4. P1-C02 needs date detection built in P1-C03, and both edit the same file. Qwen3.5 may default to "thinking" and spend the token budget before answering. Fix: move a one-case model smoke test into Phase 1; reorder P1-C02 and P1-C03; pin the generation calls and record a per-model template setting; split P3-C02 into batches and P4-C04 into two.

T10 (Important). The confidentiality guard is a narrow word list — A-3, E-1, E-2, E-3

No keyword list can contain the real names that matter; the check is not run automatically; it ignores file names, commit messages and spreadsheet files; the rule-text exemption can hide a leak on the same line. Fix: a git pre-commit hook; a private, never-committed file of names to block that only the owner fills; scan file names and reject .xlsx/.numbers; exempt rule text only in named documentation files; stage data by path, not everything at once.

T11 (Important). Model downloads are third-party code paths — E-4, E-10

Community builds are checked for size and licence but not format or integrity. Fix: weights in safetensors format only, never remote code, record repository, revision and file hashes in models.toml and load that exact revision; pin all transitive dependencies.

T12 (Minor). Prompt duplicates the guideline; delimiters can be escaped — C-5, E-8

Fix: build the prompt's definitions from the guideline and records, with a test; record the guideline version in the prompt; reject case descriptions that contain the delimiter; state that the model has no tools, so injection can only cause a wrong label, which the evaluation measures.

T13 (Minor). Untrusted text in reports and sheets — E-5, E-7, E-9

Fix: no raw model text in report.md (counts and IDs only); neutralise spreadsheet cells starting with =, +, -, @; model names only from models.toml, checked against a safe pattern.

T14 (Minor). Small gaps — A-2, A-6, A-9, A-10, B-9, B-12, C-6, C-10, C-11, D-3, D-15

Learning entry in every chunk's done-criteria; P2-C01 content list completed; BO-8 as one line; review-reason wording aligned with the tests; paired-report path named; report date from inputs, not the clock; recommendation in its own file; one guideline version per gold set; the 10-case fixture defined row by row; the stub-model interface defined.

Borderline filter
